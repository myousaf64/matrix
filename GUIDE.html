01 What this project is

Fourteen exercises that look like fourteen problems and are really about four.

You build a Vector and a Matrix type over the real numbers and implement every core operation of linear algebra without touching a maths library. Not even the one in your standard library, unless a specific exercise says otherwise.

The trick to seeing this project clearly: the last four exercises are one algorithm. Row echelon form, determinant, inverse and rank are all Gaussian elimination with a different thing recorded on the way down. Once you have the elimination engine, ex10 to ex13 cost you a few lines each.

What is actually graded

Correct output is the easy half. The subject states that the time and space complexity of every exercise will be checked during peer review, and it names two explanations you must be able to give out loud: what happens when the determinant is zero, what the determinant means geometrically, and what the rank represents. Those are in section 7. Prepare them like exam answers, because that is what they are.

02 The math

A vector space, a linear map, and one elimination algorithm that answers four questions.

Vectors and linear combination

linear_combination(v₁..vₖ, c₁..cₖ) = c₁v₁ + c₂v₂ + ... + cₖvₖ

Everything in the module is built on this. Addition and scaling are the two axioms of a vector space; a linear combination is just both at once. The subject allows a fused multiply-add here, which is exactly the shape of the inner loop: accumulate out[i] += v[i] * c.

Dot product and the three norms

u · v = ∑ uᵢvᵢ

‖v‖₁ = ∑ |vᵢ|   (taxicab)
‖v‖₂ = ( ∑ vᵢ² )1/2   (euclidean)
‖v‖∞ = max |vᵢ|   (supremum)

These are the only three exercises where extra functions are allowed, and only on ex04: the subject permits pow and max there and nowhere else. That is why norm() uses ** 0.5 and norm_inf() uses max, and why nothing else in the file does.

Cosine and cross product

cos(θ) = (u · v) / ( ‖u‖ ‖v‖ )

u × v = ( u₂v₃ − u₃v₂,   u₃v₁ − u₁v₃,   u₁v₂ − u₂v₁ )

The cosine is the dot product with the lengths divided out, so it measures direction alone. The cross product only exists in three dimensions and returns a vector perpendicular to both, with length equal to the area of the parallelogram they span.

A matrix is a linear map

(Au)ᵢ = ∑ⱼ Aᵢⱼ uⱼ     (AB)ᵢⱼ = ∑ₖ Aᵢₖ Bₖⱼ

This is the idea the whole module turns on. A matrix is not a grid of numbers, it is a function that eats a vector and returns a vector, and it does so linearly. Matrix multiplication is defined the way it is precisely so that AB is the map you get by doing B first and then A.

Gaussian elimination, the one algorithm

Three row operations leave the solution set of a linear system unchanged: swap two rows, multiply a row by a nonzero scalar, add a multiple of one row to another. Apply them systematically and any matrix reduces to reduced row echelon form: a leading 1 in each nonzero row, moving right as you go down, and zeros everywhere else in a pivot column.

The determinant, geometrically

det(A) = the signed factor by which A scales volume

Feed the unit square, or unit cube, through the map A. The determinant is the area, or volume, of what comes out. A negative determinant means the map also flipped orientation, turning a right-handed frame into a left-handed one. This is the answer the subject explicitly asks for at the defense.

What det(A) = 0 means

The map squashes space into a lower dimension: a volume becomes a flat sheet, an area becomes a line. Information is destroyed, so the map cannot be undone, so the matrix has no inverse. Equivalently: the columns are linearly dependent, the rank is less than n, and the homogeneous system Ax = 0 has solutions other than zero. All five statements are the same statement.

Rank

rank(A) = the dimension of the image of A = the number of linearly independent columns

How many dimensions survive the map. A 3×3 matrix of rank 2 sends all of space onto a plane. Counting nonzero rows of the row echelon form gives it, because elimination preserves the row space and leaves exactly one row per independent direction. The subject asks for this one out loud too.

Reduced row echelon form

    def row_echelon(self):
        a = self._copy()
        rows = len(a)
        cols = len(a[0]) if rows else 0
        lead = 0
        for r in range(rows):
            if lead >= cols:
                break
            i = r
            while abs(a[i][lead]) < EPS:
                i += 1
                if i == rows:
                    i = r
                    lead += 1
                    if lead == cols:
                        return Matrix(a)
            a[i], a[r] = a[r], a[i]
            piv = a[r][lead]
            a[r] = [x / piv for x in a[r]]
            for i in range(rows):
                if i != r:
                    f = a[i][lead]
                    a[i] = [a[i][c] - f * a[r][c] for c in range(cols)]
            lead += 1
        return Matrix(a)
matrix.py:129-154

Read it as four moves per pivot row. Find a row whose entry in the lead column is not zero, scanning down and stepping the lead column right if the whole column is zero. Swap it up into position. Divide the row by its pivot so the pivot becomes 1. Subtract multiples of it from every other row, above and below, so the rest of that column becomes 0.

Subtracting from every row rather than only the rows below is what makes this the reduced form rather than plain row echelon form. The subject's worked example expects the reduced one. Three nested loops over n give O(n³), and the single working copy gives O(n²).

Why the EPS comparison exists

EPS = 1e-10 at matrix.py:9. Floating point subtraction rarely leaves a clean 0.0; it leaves something like 1e-17. Testing a[i][lead] == 0 would then treat numerical dust as a real pivot, divide by it, and produce garbage of magnitude 1e17. Every zero test in the file goes through EPS for that reason, and the subject anticipates it: it says results may be approximate because numerical stability is hard.

Determinant, the same loop with a product

            p = max(range(i, n), key=lambda r: abs(a[r][i]))
            if abs(a[p][i]) < EPS:
                return 0.0
            if p != i:
                a[i], a[p] = a[p], a[i]
                det = -det
            det *= a[i][i]
matrix.py:162-168

Three things worth defending here. The determinant of a triangular matrix is the product of its diagonal, so eliminating downward and multiplying pivots gives the answer. A row swap flips the sign, which is why det = -det appears. And if any pivot column is entirely zero below the diagonal, the matrix is singular and the determinant is exactly 0.0, so the function returns early.

Partial pivoting: max(range(i, n), key=...) picks the row with the largest absolute value in the pivot column, not merely the first nonzero one. Dividing by the largest available pivot keeps the multipliers below 1 and stops rounding error from being amplified. This is a numerical stability choice, and it is worth naming it as one.

Inverse, the same loop on an augmented matrix

        aug = [self.rows[i][:] + [1.0 if j == i else 0.0 for j in range(n)] for i in range(n)]
matrix.py:178

Glue the identity onto the right of A to make an n × 2n block, then run Gauss-Jordan on the whole thing. Whatever sequence of row operations turns the left block into the identity turns the right block into A⁻¹, because that sequence is A⁻¹ expressed as operations. A singular matrix raises ValueError('matrix is singular, no inverse'), which matches the subject's requirement to return an error rather than a wrong answer.

Rank, three lines on top of ex10

    def rank(self):
        ref = self.row_echelon().rows
        return sum(1 for row in ref if any(abs(x) > EPS for x in row))
matrix.py:192-195

Elimination leaves one nonzero row per independent direction, so counting them gives the rank. It reuses ex10 rather than repeating the elimination, which is both less code and the honest way to show you understood that they are the same computation.

07 Eval defense

Answer out loud first, then open the block.

Two of these are not optional. The subject states in writing that you must be able to explain what happens when det(A) = 0, what the determinant represents geometrically, and what the rank represents. Expect the complexity of any exercise to be asked as well, since the subject says complexities are checked at peer review.

What does the determinant represent geometrically?

The signed factor by which the linear map scales volume. Push the unit cube through the matrix and the determinant is the volume of the parallelepiped that comes out. In two dimensions it is the area of the image of the unit square. The sign records orientation: a negative determinant means the map mirrored space, turning a right-handed frame into a left-handed one.

Concrete check: det(2I₃) = 8, because doubling all three axes multiplies volume by eight.

What happens when det(A) = 0?

The map collapses space into fewer dimensions, so volume becomes zero. A cube is flattened into a sheet, or a sheet into a line. That collapse destroys information, and no map can undo it, so A has no inverse. Five equivalent statements: the determinant is zero, the columns are linearly dependent, the rank is less than n, Ax = 0 has a nonzero solution, and the inverse does not exist. In the code, determinant() returns 0.0 early and inverse() raises ValueError('matrix is singular, no inverse').

What does the rank represent?

The number of dimensions that survive the map: the dimension of the image, equivalently the number of linearly independent columns, equivalently the number of independent rows. A 3×3 matrix of rank 2 maps all of space onto a plane. Counting the nonzero rows of the row echelon form works because elimination preserves the row space and leaves exactly one row per independent direction. The subject example [[1,2,0,0],[2,4,0,0],[-1,2,1,1]] has rank 2, because the second row is exactly twice the first.

Why are row echelon, determinant, inverse and rank all O(n cubed)?

All four are Gaussian elimination. There are n pivots; for each pivot you update up to n rows; for each row you touch up to n columns. Three nested loops of size n gives n³. Space is O(n²), because only one working copy of the matrix is alive at a time. The inverse works on an n × 2n block, which is still O(n²) since the constant 2 does not change the class.

Why does the determinant use partial pivoting rather than taking the first nonzero pivot?

Numerical stability. Every elimination step subtracts f = a[r][i]/a[i][i] times the pivot row. If the pivot is tiny, f is huge, and it amplifies whatever rounding error is already there. Choosing the largest absolute pivot in the column keeps every |f| ≤ 1, so errors shrink rather than grow. It costs one extra scan of the column and does not change the O(n³) class.

Why compare against EPS instead of testing equality with zero?

Because floating point subtraction of two nearly equal numbers leaves dust rather than a clean zero: something like 1e-17, not 0.0. An exact equality test would treat that dust as a valid pivot, divide by it, and blow the matrix up by seventeen orders of magnitude. EPS = 1e-10 at matrix.py:9 is the threshold below which a value is treated as structurally zero.

What is the difference between row echelon form and reduced row echelon form, and which did you implement?

Row echelon form only requires zeros below each pivot, and the pivots need not be 1. Reduced row echelon form additionally requires each pivot to be exactly 1 and the rest of its column to be zero above as well as below. This code implements the reduced form: it divides the pivot row by the pivot, then eliminates over every row i != r, not just the ones below. The subject's worked example expects the reduced form, and the reduced form is unique for a given matrix, which is why it can be tested by comparison at all.

Why is the inverse computed on [A | I]?

Every row operation is itself a matrix multiplication on the left. The sequence of operations that reduces A to I is therefore some matrix E with EA = I, which means E = A⁻¹. Applying that same sequence to the identity computes EI = E. So reducing the left block to the identity leaves the inverse sitting in the right block, with no separate bookkeeping.

Which functions did you use, and does the subject allow them?

The subject forbids any mathematical library including the standard one, and lists the allowed functions per exercise. matrix.py has no imports at all. ** 0.5 in norm() is pow, and max in norm_inf() is max, both of which are explicitly allowed on ex04, the only exercise that allows them. Elsewhere the arithmetic is + - * /, plus abs and the builtins sum, zip and max used for selection rather than as a maths function. See the traps section for the one place that is worth raising before the evaluator does.

Why is lerp one line, and why does it work on matrices as well as numbers?

u + (v - u) * t is written only in terms of addition, subtraction and scaling, which are exactly the operations a vector space guarantees. Vector and Matrix each define __add__, __sub__ and __mul__, and plain Python floats already have them, so the same line covers all three. That is the generic implementation the subject asks for, expressed in Python's idiom rather than Rust's.

What is the complexity of matrix multiplication and why?

O(nmp) time for an m × n matrix times an n × p matrix: every one of the m × p output cells is a sum over n terms. The subject sets space at O(nm + mp + np), which is the two inputs plus the output. The implementation at matrix.py:109 orders its loops i, k, j rather than i, j, k so the pivot value aik is hoisted out of the inner loop, and it writes into a preallocated output.

Why does the trace only make sense for a square matrix?

The trace sums a[i][i], which requires a diagonal, and only a square matrix has one. Its deeper meaning is that it equals the sum of the eigenvalues, and unlike almost anything else built from the entries it is unchanged by a change of basis, so it is a genuine property of the linear map rather than of the particular grid of numbers.

Why is the cross product only defined in three dimensions?

Because only in three dimensions is the space perpendicular to two independent vectors itself one dimensional, so there is a single natural answer up to sign. In two dimensions the perpendicular space is a line but there is no plane to span; in four, the perpendicular space is two dimensional and no single vector is distinguished. The general construction that does survive to all dimensions is the wedge product, which returns a plane element rather than a vector.

Why does the subject cap the determinant at 4 by 4?

To stop students from submitting the cofactor expansion, which is O(n!) and becomes unusable almost immediately. Capping the size makes the exercise tractable either way, while the stated O(n³) bound forces the elimination approach. This implementation is elimination based, so it has no real size cap; the 4×4 limit is the subject's, not the code's.

What is the cosine of the angle telling you that the dot product alone is not?

The dot product mixes direction and magnitude: it grows if you simply make either vector longer. Dividing by both norms cancels the magnitudes and leaves pure direction, always between -1 and 1. 1 is the same direction, 0 is perpendicular, -1 is opposite, which is the subject's example with [-1, 1] and [1, -1].

How would you extend this to complex numbers, as bonus ex15 asks?

Most of the module is already written against the operators rather than against floats, so a Complex class defining __add__, __sub__, __mul__ and __truediv__ would carry it. Two real changes are needed. The constructors at matrix.py:14 and matrix.py:65 hard cast every entry with float(x), which would have to go, and that cast is the actual blocker. And the dot product would need to conjugate the first argument, since over the complex numbers the inner product is ∑ conj(uᵢ) vᵢ, otherwise ‖v‖² is no longer real and positive.

Two honest weak points to raise yourself

1. max with a key inside determinant and inverse. matrix.py:162 and matrix.py:180 use max(range(i, n), key=lambda r: abs(a[r][i])) to select the pivot row. Only ex04 lists max as an allowed mathematical function. The defence is that this is Python's generic selection builtin choosing an index, not a mathematical operation on values, and that it can be replaced by a three-line loop with no change in complexity. Say it before the evaluator finds it, and offer the loop.

2. The float cast blocks genericity. matrix.py:14 and matrix.py:65 call float(x) on every entry. The subject asks for an implementation generic in K, and this pins K to the reals. For the mandatory part, where K = f32, it is fine and the subject only requires the reals. It is the one line that would have to be removed for bonus ex15.

The column-major footnote

The subject says: "Unless specified otherwise, all matrices shown in the examples are in column-major order." This code stores and prints row-major, and the worked examples still match, because the subject's own examples are laid out so that reading them the natural way gives the expected results. Be ready to state which convention you store in, since a confused evaluator may ask.
